# 项目背景与设计理念

## 为什么做共端

服务器维护常要求先由人完成 SSH 登录、主机指纹确认、密码或密钥口令输入，再通过 `su` 切换权限。Agent 独立新建一次性 SSH 命令会失去用户当前 Shell 的权限、环境变量、工作目录和运行中的程序，也难以让双方确认究竟操作了哪条连接。

共端把一个真实 SSH 会话变成可协作的终端。用户先完成需要本人处理的步骤，再把同一会话交给 Agent；任何时候都能看见操作进展并接管。项目不代管 VPN、堡垒机或跳板机；当前保存的 Host 直接连接对应服务器。

## 产品定位

本地运行的用户与 Agent 协作 SSH 平台：共享画面、独占输入、随时交接。它既不是隐藏执行器，也不为 Agent 另开一条看不见的管理连接。

多个 Agent 应用与多个项目可同时使用，一个 Agent 可以关联多条 SSH 会话。同一服务器可建立多个相互独立的页签；Host + 用户相同不意味着会话相同，唯一标识始终是 sessionId。

## 用户与 Agent 所见即所得

服务端的 xterm 缓冲区是终端内容的唯一来源。用户页面从该缓冲区恢复画面，Agent 读取同一屏幕和最多 2000 行保留滚动历史。不同窗口可以滚动到不同位置，但在各自权限内可访问的终端内容范围相同。

- 未发送的输入若由远端回显，就出现在共同画面中；不提供单独的原始用户按键日志。
- Vim、top 使用的备用屏幕也属于同一个终端；切换输入方不会退出程序。
- 覆盖、滚出保留范围和清空的内容不能通过隐藏原始日志再次读取。
- 用户“清空全部历史”会同步清空终端内容和独立消息历史；这不能撤回已经送入某个 Agent 上下文的内容。
- SSH 关闭但页签仍在时，用户和已授权 Agent 均可只读查看保留内容。移除页签后不再提供历史。
- 浏览器关闭只断开观察连接；SSH 由本机服务持有。服务重启才结束这些 SSH 进程。
- 密码提示是否回显由提示程序决定。正常 `su` 不回显密码，但误在 Shell 输入、粘贴到错误位置或异常程序回显仍会出现在共同画面。

## 三个独立的权限维度

| 维度 | 含义 | 对其他维度的影响 |
| --- | --- | --- |
| 关联 Agent | 哪个任务身份获准访问这个 sessionId | 不自动夺取输入权 |
| 输入权 | 当前哪个用户页面或 Agent 能向 PTY 写入 | 释放不结束程序、不撤销关联 |
| 私密 | 是否禁止 Agent 观察、认领、读取消息和输入 | 不清屏、不改变锁、不结束程序 |

用户页面之间同样独占输入，每个页面都有自己的身份；一个页面输入结束不会自动让另一页面获得锁。“接管输入权”和“释放输入权”同时显示，状态变化由服务端推送。Agent 只能获取空闲锁；用户可以强制接管，令旧 lease 立即失效。

关联仅面向具体任务身份。A 持输入锁时 B 无法替换关联；A 释放或用户接管后，B 在得到用户提供的 sessionId 后可以认领。默认会话列表只列当前任务的连接，全部列表仅展示元数据。

## 协作消息

用户可以在终端旁向关联 Agent 发消息，无需抢占输入权。消息通过本地服务投递，绝不成为 SSH 按键或 Shell 注释，也不从远端输出中识别指令。

通知只表达“有消息”。客户端是否唤醒模型、是否将其排队或作为引导，由客户端决定。未确认消息仍可在工具返回中看到，并可显式读取。用户面板区分“待确认收到”和“Agent 已确认收到”；不能把后者解释为完成了请求。

## 明确不承诺的能力

不保证判断任意命令何时结束，不提供准确命令退出码，不自动释放输入权，不推断空闲 Shell。没有独立文件下载编辑通道，不绕过远端账户权限、命令限制或审计。当前也不保证任意 MCP 客户端支持主动唤醒聊天。
