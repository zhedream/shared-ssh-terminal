# 架构与数据流

## 组件

```text
Agent 应用 A ── stdio MCP ── 适配进程 A ─┐
Agent 应用 B ── stdio MCP ── 适配进程 B ─┼── HTTP ── 本机单例服务 ── ConPTY + ssh.exe ── 远端 PTY
用户浏览器页面 1/2 ──────────────────────┘     HTTP + WebSocket
```

单例服务默认仅监听 `127.0.0.1:43127`，持有所有 SSH 和状态。每个 MCP 应用启动自己的 stdio 适配进程，适配进程不监听新端口。`.runtime/connection.json` 供适配进程发现服务地址，避免各项目硬编码独立端口。

浏览器负责显示及人工输入，MCP 负责结构化工具调用。两种入口最终访问同一 Session；消息是独立的本机服务数据，不经过远端。

## 内容、同步与生命周期

每个 Session 有唯一 id、创建来源、关联 Agent、私密状态、输入锁、终端尺寸、状态修订和 historyEpoch。PTY 输出写入 headless xterm 后才广播给页面；Agent 屏幕快照排在同一渲染队列中，避免读到尚未完成解析的内容。

新页面先完成鉴权，接收所有会话快照和消息历史，再补发快照期间缓存的状态事件；revision 和 sequence 用于区别控制状态与终端输出。输入串行确认，冲突、断线或超时后不会自动重试，避免重复执行。

输入锁的 lease 只给真实持有者，不在公开摘要中返回。用户输入带页面身份和最新 revision，Agent 输入带任务身份和有效 lease；会话、关联、私密和锁都在服务端校验。

清空使用终端缓冲区操作，而不是往远端输入 `clear`。epoch 使并发读取不能返回被清空前的旧快照。关闭保留只读页签；移除页签删除内存对象并跨页面广播。服务重启不恢复远端进程或终端历史。

## 本机认证

服务启动时生成不同的 UI 和 MCP bearer token。浏览器入口中的令牌经验证后保存在本机浏览器，地址栏 hash 被移除。HTTP 检查 Host、Origin 和 bearer；WebSocket 限制同源并在握手后验证令牌。

MCP 适配进程为每个项目/聊天 `register_agent`，产生独立任务 ID 和 secret。服务端绑定身份与 secret，不能仅凭可见名称冒充。连接重启时适配进程会向新服务重新注册，但不会恢复已结束的 SSH。

## SSH 配置与密码

profiles 独立维护，SSH config 导入只复制允许字段，不执行 Match exec 或 ProxyCommand。系统 SSH 用 `-F NUL` 避免隐式叠加其他配置；known_hosts 放在本机 data 目录，首次指纹由用户确认。

手动密码和密钥口令沿用 OpenSSH 的交互。已保存的密码通过 Windows DPAPI CurrentUser 加密；服务只在认证时解密，经随机能力令牌保护的本机命名管道交给 askpass 小组件。密码不进入环境变量、进程参数、原始 PTY 输入或工具返回。

askpass 仅对本次端点的标准密码提示自动提供一次保存值；主机确认和进一步提问仍交给用户，回答不回显。保存密码模式只请求标准 password 认证，不自动填写验证码。端点信息变化时必须重新保存密码，避免把凭据发给另一台服务器。

## 消息与通知

Messages 模块只存有界内存数据，每会话最多 100 条。发送固定目标 Agent，读取需同时满足目标身份匹配、仍有关联且私密关闭。消息正文由身份校验后的工具读取；MCP 标准日志通知只携带消息存在提示与路由 ID。

每个已注册上下文使用认证的 HTTP 长轮询等待消息变化，stdio 适配端转成 `notifications/message`。通知不需要新端口。工具结果中的独立附加文本作为未确认消息的兜底，不改变既有工具的主结果结构。

## 部署边界

当前是 Windows 本机应用，不是公共多用户 SaaS。持有本机 UI 令牌的人被视为本机用户，有权接管和管理会话。本机服务没有自动升级、远端共享账户系统或基于网络的多租户隔离；不要直接暴露到公网。
