# 私密资料与公开发布

## 不得进入仓库的资料

- `data/`：真实服务器列表、账户、私钥路径、密码密文、known_hosts。
- 实例运行目录（包括旧 `.runtime/`）：回环管理和 MCP 令牌、配对签名密钥、服务进程信息、日志、测试密钥和操作产物。
- SSH 私钥、口令、真实环境变量、个人配置、备份压缩包、截图、附件和终端操作记录。
- 含真实 Host/IP、个人目录、内部域名和生产配置的示例。使用 localhost、example.com 或文档保留地址。

密码密文也不提交：它仍是凭据相关资料，并且会把本机配置带入项目历史。`.gitignore` 是第一层保护，不能阻止已跟踪文件或强制添加。

## 提交与首次推送流程

1. 在项目自身目录初始化 Git，不把父目录及附件纳入。
2. 明确添加源码、测试、文档、包配置和通用启动脚本，不直接无检查地添加整个工作区。
3. 运行 `git diff --cached --stat` 与 `git diff --cached` 查看真实暂存内容。
4. 运行 `npm run check:publish`。脚本从 Git 索引读取待提交版本，而不是仅扫描工作区；拒绝私密目录、常见密钥/令牌、本机个人路径和当前配置中的实际主机值。
5. 运行测试与文档检查，再提交。首次提交没有需要继承的私密历史；不要把开发日志迁移成 Git 提交历史。
6. 默认先推私有仓库。以后公开前再次检查全部历史、分支、标签、release 和 CI 产物，并由所有者选择开源许可证。

扫描不能识别所有秘密。例如未配置在本机 profiles 中的内部域名、业务敏感文本和新格式令牌仍需人工检查。本项目不因扫描通过就宣称绝无泄露。

## 开发测试与凭据

测试只生成临时密钥、虚构密码，连接本机临时 SSH 服务。临时材料放在被忽略目录。生产登录验证应由用户在界面输入，不把密码写进工具参数、聊天、命令行或测试文件。

配对浏览器拥有共端的会话权限，可查看和接管终端。只向获准操作 SSH 的成员发配对链接。局域网 HTTPS 应限定在可信网段，浏览器须验证证书。管理和 MCP 保持回环。保护 TLS 私钥、配对签名密钥、未兑配对码、Cookie、管理／MCP bearer 和 Agent 任务 secret，避免写入日志、截图或公开记录。[局域网 HTTPS](development.md#局域网-https)

## 所见即所得的安全边界

Agent 读取的是共享内容，不是本地窗口像素，也不是所有远端文件的隐式权限。文件通过 Vim 等工具显示后会进入共同画面；若政策禁止向 AI 提供内容，用户必须开启私密或完全不授权该环境。私密不能撤回此前已读取的数据。

发现凭据误提交时，不仅删除文件，还需立即吊销/轮换凭据并处理历史。重写远端历史属于破坏性操作，需要所有者明确授权及协作者协调。
