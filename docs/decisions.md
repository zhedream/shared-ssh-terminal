# 设计决策记录

## 单例服务和独立 stdio 适配端

多个应用都可能启动 MCP，如果各自持有 SSH，会出现相同服务器上状态和输入锁彼此独立的问题。服务统一持有会话，适配端只转交请求；不因为项目数量增加监听端口。

## 身份与关联不能用 Host 替代

同一服务器可同时服务多个 Agent 和项目。使用任务身份和 sessionId 防止串会话；列表默认只看自己的连接。用户创建的会话先待交接，由用户复制 sessionId 指定访问对象。

## 页面之间也保持唯一输入权

采用多页面共同观察、单页面输入的协作方式，避免同时按键交错。用户能随时接管另一页面或 Agent，Agent 仅可获取空闲锁。释放输入权只改变持有者，不影响运行中的 top、Vim 或未发送输入。

## 移除 Shell 完成检测

早期原型曾用 Shell 回调、提示符标记和包装命令检测结束。它会向终端和 Shell 历史写入初始化命令，并依赖 Bash/Zsh 及提示符状态；在密码提示、嵌套 Shell 和交互程序中还会混淆“结束”和“可以交接”。

最终选择完整移除：不保留启用入口或隐藏兼容工具；双方发送原始按键，观察当前画面判断进展，并主动释放输入权。接受无法提供通用准确退出码和自动完成解锁的限制，以换取与人工操作一致、对服务器无额外 Shell 改造的行为。

## 唯一保留画面，不存隐藏终端日志

拼接原始输出会在 `clear`、覆盖和备用屏幕退出后仍暴露用户已经看不到的内容。选用 canonical xterm 缓冲区，覆盖和滚动淘汰同样作用于 MCP。清空不代表删除远端 Shell 自身的历史，也不能撤销模型已有上下文。

## 私密独立于输入权

用户接管并不意味着一切操作都私密。私密只控制 Agent 的访问，不自动擦除画面；关闭后可共享当前保留内容。必须明确告知其边界，不能暗示关闭私密后敏感历史自动消失。

## 最新优先并限制读取预算

整份保留缓冲区虽然保持了所见即所得，却会在每次观察时重复占用模型上下文。0.6 改为按任务独立记录当前画面哈希，默认只给最新受限画面及变化，历史从最近处向前显式分页。未观察的积压不意味着必须自动补齐；超过预算的旧变化被明确标注，交给 Agent 决定是否另取。Vim 等备用屏幕优先展示当前程序，普通历史有独立且双方都可访问的入口。

读取采用字符和行数硬上限而非承诺精确 Token 数。记录过期时不从保存的旧页重放，而是要求重新读取当前内容，接受动态输出期间分页可能失效的限制，以避免清空后再看到旧内容。

## 消息独立于 Shell 和输入锁

Shell 注释受设置影响，并不适用于 Vim 或密码提示。用户消息只由本地 UI 明确发送，不从远端输出中提取。通知保留为连接级提示，正文用任务身份读取，且以显式确认区分“投递”和“收到”。

## 密码只保存在当前 Windows 账户下

使用系统 DPAPI 保护而不是在项目中保存明文或自制静态密钥。加密文件仍是私密资料，不可提交。通过 askpass 传递凭据，避免根据终端文本猜测密码提示后把密码打进 Shell。
